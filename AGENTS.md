# Attribute Manager — Agent Guide

## What This Is
A dockable Maya 2024.2 panel (Python 3 + PySide6) that aggregates scene attributes into grouped, draggable, editable rows. Tested on Maya 2024.2 only — other Maya versions are untested. Config persists inside the scene file on a locked `network` node named `attrManager`. Referenced scenes' configs are displayed read-only, with per-scene overrides supported in place.

## Running
No build step. In Maya Script Editor:
```python
exec(compile(open(r"C:\opencode\attributeManager_maya\launch.py").read(), r"C:\opencode\attributeManager_maya\launch.py", "exec"))
```
`launch()` hot-reloads all modules automatically. The launcher auto-configures `sys.path` — no manual setup needed.

## Architecture
- `attributeManager.py` — entry point, module reload, `__init__.py` re-exports `launch`/`reload_modules` from it.
- `core/attr_data.py` — pure dataclasses (AttrEntry, AttrGroup, Config) + JSON serialisation. No Maya imports except `resolve_entries()`. `Config.slider_float_precision` is a global Int/Float Snap flag.
- `core/scene_io.py` — reads/writes config JSON to a locked `network` node (`attrManager.config`). `save_config()` disables undo around the WHOLE operation (node create, `lockNode`, lock-state `setAttr`, JSON write) so it adds zero undo entries. `get_or_create_node()` handles a same-named non-network node by warning + creating `attrManager1`; `_config_nodes()` falls back to prefix matching. `load_config()` merges referenced-node configs into the main config, tagging `reference_namespace`/`is_referenced` (`is_referenced` is a runtime flag derived at load time — NEVER serialised; reference identity persists on the group via `reference_namespace`).
- `core/merge.py` — pure-data transforms between the merged display structure and the persisted config (no Maya/Qt imports, unit-tested in `tests/`). `merge_for_display()` moves override entries from main groups into their referenced group's original position; `collect_for_save()` is the inverse (main groups + overrides gathered into store groups); `entry_key()` is the (uuid-or-path, attr) override-matching identity. `is_referenced` round-trips through neither direction — it is re-derived at load.
- `core/channel_box.py` — queries Channel Box selected attributes (main + shape); also holds `record_set_attr`/`get_last_set_attr` for the "+ Last Lock Attr" feature. `record_set_attr` is called after every successful panel `setAttr`; `enable_command_hook()` registers an `MCommandMessage.addCommandCallback` that records `setAttr` commands from the MEL/command-system channel — MEL scripts, and Attribute Editor right-click actions such as Lock (which echoes `setAttr "-l" 1 {"node.attr"};`) — but NOT Python `cmds` calls or plain Channel Box edits. A right-click Lock is treated as an "add to Attribute Manager" gesture: the plug is recorded but LEFT LOCKED — it is only unlocked via `unlock_attr()` when the Add dialog actually adds it (see `main_window._on_add_accepted`), so real lock intentions are never hijacked. `get_last_set_attr()` reads the recorded plug (never consumed, stays "most recent"); there is no Script Editor history fallback. `_parse_set_attr_line` locates the plug by token scan (stripping quotes/braces, skipping `-flag` tokens), so `-type` may precede OR follow the plug (e.g. `setAttr -type double3 "pCube1.color" 1 2 3;`) and AE Lock echoes `{"plug"}`-style braces — a fixed-position regex matched none of those. The hook uses `maya.api.OpenMaya` (API 2.0): API 1.0's `addCommandCallback` returns an opaque PyCapsule that `removeCallback` cannot consume, silently leaking a live callback. `_hook_enabled` gates BOTH `_on_command` and `record_set_attr` (panel-recorded plugs too), so a stale callback surviving a reload/remove-failure can never record once `disable_command_hook()` has run — `record_set_attr` reads the flag through the module dict at call time, which also neutralises pre-flag versions of the callback. `launch.py` must call `disable_command_hook()` BEFORE reloading the module, or the old callback leaks in the OpenMaya layer (fires into the old module's globals the reloaded module can't see).
- `ui/main_window.py` — `MayaQWidgetDockableMixin` + `QMainWindow`. Contains `GroupContainer` (group-level drop target) and `move_group`/`move_entry` logic. `load_scene_config()` reads + merges via `_apply_merged()` which delegates the data transform to `core/merge.merge_for_display` (separation allows in-memory re-merge after override creation). `_do_save()` delegates to `core/merge.collect_for_save` — it collects main groups **plus overrides living inside ref-group display structures** — the data source of truth, not the display snapshot. Save is 300ms-debounced via `_save_timer` whose timeout routes through `maya.utils.executeDeferred` (`_save_timeout`/`_save_guard`). Toolbar has Int/Float Snap toggle. Registers `SceneOpened`/`Undo`/`Redo` scriptJobs (NO `SceneCreated` — it does not exist in Maya 2024; `newFile` fires `SceneOpened` anyway) plus MSceneMessage callbacks (`_enable_scene_message_callbacks`/`_disable_scene_message_callbacks`, module-level `_scene_callbacks`): `kAfterReference`/`kAfterReferenceEdit`/`kAfterLoadReference`/`kAfterUnloadReference`/`kAfterImport` all route to `_schedule_reload` (150ms-debounced `_reload_timer` → `_deferred_load`) so creating/loading/unloading a reference or importing re-reads the config — without it a freshly referenced `attrManager` config never appears until reload/reopen. The enum constants differ across Maya builds, so each is probed with `getattr(om2.MSceneMessage, name, None)` and silently skipped when missing (e.g. `kAfterReferenceEdit` does not exist in Maya 2024's API 2.0). Undo/Redo run a deferred `refresh_all_values()`. `launch()` calls `_kill_stale_jobs()` before rebuilding; it REUSES an existing workspace control (close, rebuild the window, `_attach_to_workspace` via `MQtUtil.addWidgetToMayaLayout`) instead of `deleteUI` so Maya's retained dock position survives restarts; new windows use the two-step `show(dockable=True, floating=True)` then `show(dockable=True, area="right", floating=False)` (single-step falls back to a floating window + blank workspace control). `_set_ui_script()` stores a `python(...)`-safe uiScript (bare Python defining `__file__` then `exec`-ing `launch.py`) so Maya rebuilds the panel on session restore (`_restore_from_ui_script`); a `visibleChangeCommand` refetches config on reopen and flushes pending save on close. `rebuild()` first closes any abandoned slider chunks tracked in `_slider_chunks`. `LEGACY_WORKSPACE_NAME` (`attrManagerMainWindowWorkspaceControl`) is deleted on launch.
- `ui/group_section.py` — collapsible group with `EntryContainer` (entry-level drop target, #5285a6 indicator line). `GroupDragHandle` distinguishes click (collapse) vs drag (reorder) by 8px threshold. Empty groups show a `dropPlaceholder` QLabel (via `_ensure_placeholder()`); `_entry_widgets()` excludes the placeholder from index math. Referenced groups are read-only: drag/reorder and entry drops are blocked. `_remove_entry()` has a special branch: removing an override row shown inside a ref group also purges the override from the main config (`window.remove_override_entry` → `_do_save` → `load_scene_config`), restoring the read-only ref entry.
- `ui/attr_row_widget.py` — per-attribute row: DragHandle, name (double-click rename), type-matched editor. Numeric rows: SpinBox + Slider; slider right-click opens Set Min/Max/Range/Reset menu (`RangeDialog`); slider drags are wrapped in ONE undo chunk via `sliderPressed/Released` + `_set_value(..., skip_chunk=True)`, and `skip_chunk` is forwarded into `_create_override_and_set` so referenced-entry drags stay a single undo step. `ColorButton` opens `cmds.colorEditor`. `display_type` (auto/number/color) can override auto-detection. Editing a referenced entry creates an in-place override: the override entry is stored in the main config, merged back into the ref group's original position (`_apply_merged`), and marked with an "override" badge. `_is_override_display()` also badges main-group entries whose node belongs to a reference (`_node_is_referenced`). `exists` detection scans all groups (incl. ref-group overrides) to avoid duplicate override entries.
- `ui/add_attr_dialog.py` — non-modal dialog; Channel Box or manual plug input; searches transform + shapes via `_find_attr_owner`. Has Display type (Auto/Number/Color) radio group and a "+ Last Lock Attr" button that fills the plug from the most recent Lock gesture. The target-group combo ends with a "New Group..." item (userData None) that prompts for a name and inserts the new group above it; a group created this way but left empty is rolled back on `reject()`. Target-group combo skips referenced groups; `main_window.add_attributes()` guarantees at least one non-referenced target group exists first.
- `ui/styles.py` — global QSS (Maya Channel Box gray theme, #464646 bg; #5285a6 accent for text/list selection highlight and drag indicators).

## Critical Gotchas
- **UUID lookup**: Use `cmds.ls(uuid_string, long=True)`. Do NOT use `cmds.ls(uuid=uuid_string)` — the `-uuid` flag is boolean and returns ALL uuids.
- **Dockable window reopen**: Must `cmds.deleteUI(objectName + "WorkspaceControl")` before creating a new instance, or Maya raises "name not unique". Also kill the old window's scriptJobs before closing, or stale jobs survive and reference destroyed objects.
- **Dockable show is two-step**: `show(dockable=True, area=..., floating=False)` on a brand-new window silently falls back to a FLOATING workspace control (window never reparents), leaving a blank dock panel. Always do `show(dockable=True, floating=True)` first, then `show(dockable=True, area="right", floating=False)`.
- **`closeCommand` does not fire**: workspaceControl's `closeCommand` (mixin `closeCallback`) is unreliable in Maya 2024; use `visibleChangeCommand` + query the control's own visible state instead (the callback arg is an empty string, not the state).
- **Workspace layout persistence**: `deleteUI(workspaceControl, control=True)` clears Maya's retained layout record (stored in `prefs/workspaces/General.json`). `launch()` must NOT delete an existing workspace control — close it, rebuild the window, and re-attach via `MQtUtil.addWidgetToMayaLayout` (`_attach_to_workspace`) so the dock position survives restarts.
- **Dock close then relaunch hides the window**: after closing the workspace control via its dock X, relaunching re-attaches the new window into the CLOSED control — the panel flashes and vanishes while the attach still reports success (the window IS the control's child, just hidden with it). Must `workspaceControl(workspace, edit=True, restore=True)` BEFORE `addWidgetToMayaLayout` (see `_attach_to_workspace`); if restore fails, bail out so `launch()` falls back to deleting and rebuilding the control.
- **uiScript restores the panel on restart**: set `workspaceControl(... -e -uiScript ...)` so Maya rebuilds the panel automatically when it restores the retained control. The Python `workspaceControl` command treats `uiScript` as PYTHON code — pass bare Python, NOT a `python("...")` MEL wrapper (Maya wraps it into `python("...")` itself when persisting; a pre-wrapped string becomes double-nested and fails with NameError).
- **uiScript must define `__file__`**: `launch.py` reads `__file__` at module top (`_SCRIPT_DIR`), so the uiScript string must first assign `__file__ = r'<path>'` before `exec(compile(open(__file__).read(), __file__, 'exec'))`, exactly like the manual Script Editor invocation. Use forward slashes in the path to survive MEL/JSON escaping.
- **Legacy workspace name**: older builds used `attrManagerMainWindowWorkspaceControl`; Maya's `General.json` may still hold a stale record. `launch()` deletes it (`LEGACY_WORKSPACE_NAME`).
- **SceneCreated does not exist**: `cmds.scriptJob(event=["SceneCreated", ...])` raises "Could not find condition or event named SceneCreated". `newFile` fires `SceneOpened`, so listening to `SceneOpened` alone covers both Open and New.
- **Reference changes fire no panel event**: creating/loading/unloading a reference does NOT fire `SceneOpened` and produces no undo entry, so a panel that only listens to `SceneOpened`/`Undo`/`Redo` never shows a freshly referenced `attrManager` config until reload or scene reopen. There is ALSO no scriptJob event to catch this — `scriptJob(event=["referenceStateChanged", ...])` raises "Could not find condition or event named referenceStateChanged" (which fails window construction if not caught). Use `MSceneMessage` API 2.0 callbacks instead (`kAfterReference`/`kAfterReferenceEdit`/`kAfterLoadReference`/`kAfterUnloadReference`/`kAfterImport`), debounced before re-reading the config — see `_enable_scene_message_callbacks`/`_schedule_reload`/`_reload_timer`. Old callbacks must be removed before module reload (`launch.py` calls `_disable_scene_message_callbacks()`), or they leak like the command hook.
- **Display structure ≠ persisted truth**: `_apply_merged` moves override entries from main groups into ref groups for display. `_do_save` MUST collect overrides from inside ref-group display structures too (`[e for e in group.entries if not e.is_referenced]`), or the debounced save overwrites the config WITHOUT the override — reload loses the override and its badge.
- **Undo chunks and save**: `undoInfo(stateWithoutFlush=False)` works fine inside an open chunk and from normal command context. BUT in a command-port/headless context (no full event loop), save_config called from inside a Qt callback (QTimer/signal) corrupts the undo queue — verified only in that environment; real Maya UI interactions undo correctly. Test undo behaviour in a real Maya session.
- **`closeChunk` probe is unreliable**: Maya 2024's `undoInfo(closeChunk=True)` succeeds silently when no chunk is open (no exception). Never write a `while True: closeChunk` drain loop — it hangs the Maya main thread.
- **Abandoned slider chunks**: dragging a referenced entry's slider triggers `rebuild()`, destroying the slider, so `sliderReleased` (which closes the undo chunk) may never fire. Track pressed rows in `window._slider_chunks` (`_slider_pressed` adds, `_slider_released` discards) and close leftover chunks at the top of `rebuild()`.
- **PySide6 `exec`**: `QDialog.exec_()` and `QDrag.exec_()` removed in PySide6. Use `hasattr(obj, "exec")` guard.
- **PySide2 `QAction`**: Lives in `QtWidgets` (PySide2), NOT `QtGui`. PySide6 moved it to `QtGui`. Import from the correct module in each try/except branch.
- **Maya focus**: `QApplication.focusChanged` does not fire when clicking Maya viewport. Use `QTimer(200ms)` polling `hasFocus()` for rename confirmation.
- **`attributeQuery` min/max**: `minimum=True` throws if attr has no min. Must check `min=True` first (returns [bool]) or wrap in try/except.
- **`EntryContainer._layout`**: Named `_layout` (not `layout`) to avoid shadowing `QWidget.layout()`.
- **Drag events**: `QLabel` does not accept mouse press by default. Must call `event.accept()` in `mousePressEvent` to get implicit grab and receive `mouseMoveEvent`.
- **`normalise_orders()`**: Sorts by `.order` field. After any list reorder, update `.order` values BEFORE calling `rebuild()` (which calls `normalise_orders`), or the move is silently reverted.
- **Shape attributes**: `cmds.ls(sl=True)` returns transforms only. Use `cmds.listRelatives(node, shapes=True)` to find shape attrs. Channel Box shape attrs need `-selectedShapeAttributes` flag.
- **`evalDeferred`**: Takes a string, not a Python callable. For deferred Python function calls use `maya.utils.executeDeferred(func, lowPriority=True)`.
- **Slider precision**: Slider is integer-based; precision comes from `_get_slider_precision()` (1 for Int Snap, 1000 for Float Snap). `refresh_value` MUST use the same helper or values get clamped to wrong positions.
- **Slider undo**: `sliderPressed` opens an undo chunk, `sliderReleased` closes it, and `_slider_changed` calls `_set_value(..., skip_chunk=True)`; `skip_chunk` must be forwarded to `_create_override_and_set` so a referenced-entry drag is ONE undoable action, not two nested chunks.
- **`executeDeferred` kwargs**: Some Maya builds forward keyword args (e.g. `lowPriority`) to the deferred callable, causing `unexpected keyword argument`. Wrap callbacks in a guard that accepts `*args, **kwargs` (see `_load_guard`/`_refresh_guard`/`_save_guard`) rather than passing the target method directly.
- **Dock close ≠ `closeEvent`**: Closing a docked `MayaQWidgetDockableMixin` window does NOT fire `closeEvent`, so its scriptJobs survive. `launch()` must scan `cmds.scriptJob(listJobs=True)` and kill jobs matching the window (see `_kill_stale_jobs`/`_active_jobs`), or stale `Undo`/`Redo` jobs accumulate across reloads.
- **Config save undo**: `lockNode`, lock-state `setAttr`, `addAttr`, and `createNode` are ALL undoable. Disable undo (`undoInfo(stateWithoutFlush=False)`) around the ENTIRE `save_config()` — not just the JSON `setAttr` — or every save injects several blank undo entries (pressing Ctrl+Z many times before a real undo).
- **Deleted Qt widgets**: After a rebuild/reload, row Python objects can outlive their C++ widgets. Guard `refresh_value()` with `shiboken.isValid(widget)` before `property()`/`setValue`, or it raises "Internal C++ object already deleted".
- **Rename focus jump**: Hiding a focused `QLineEdit` hands focus to the next widget in the chain (value editor / delete button). Capture `hasFocus()` before hiding and, if true, redirect focus to the row/group itself (which needs `setFocusPolicy(Qt.ClickFocus)`).
- **Empty-group drop**: An empty `EntryContainer` collapses to ~0 height and cannot receive drops. Show a placeholder widget when a group has no entries to keep it a droppable area.
- **Referenced-group protection**: Ref groups are read-only — `GroupDragHandle` drag is blocked, `EntryContainer` rejects drops, `move_group`/`move_entry` refuse ref groups, and `AddAttrDialog` filters them from the target combo. `_do_save` never touches ref groups (their overrides are collected into standalone store groups).
- **Override badge**: Any entry whose node belongs to a reference file (`referenceQuery(isNodeReferenced=True)`) shows the "override" badge, whether it displays in a ref group (in-place override) or a main group (e.g. Translate Z added manually from a ref node). Removing such a row from a ref group purges the main-config override and restores the read-only ref entry.

## Conventions
- No comments unless requested.
- `from __future__ import annotations` in every module.
- PySide6 primary, PySide2 fallback via try/except at top of each UI file.
- Non-slider `cmds.setAttr` wrapped in `undoInfo(openChunk/closeChunk)`; slider drags use the press/release chunk pattern instead; `skip_chunk` is forwarded into override creation so referenced drags stay one undo step.
- `record_set_attr` is called ONLY after a successful `cmds.setAttr` (so failed sets don't poison the Last Lock Attr feature). The global command hook (see `core/channel_box.py`) additionally records MEL-channel `setAttr`s; it is enabled in `_create_jobs`/disabled in `_teardown`, and `launch.py` disables the old hook before each reload.
- Config saves disable undo (`undoInfo(stateWithoutFlush=False)`) around the WHOLE `save_config()` (including `lockNode`/lock toggles) to keep the undo stack clean; window-level `save()` is debounced 300ms via `QTimer`, and the timeout defers through `maya.utils.executeDeferred` (see `_save_timeout`/`_save_guard`).
- Data model is single source of truth; UI rebuilds from it. `_apply_merged` re-merges an in-memory config for display after override creation without a scene re-read.
- `_do_save` persists main groups plus overrides living inside ref-group display structures (store groups named after the ref group), so debounced saves never drop overrides.
- Override removal from a ref-group row must purge the main-config override and reload the merged display (`remove_override_entry` + `_do_save` + `load_scene_config`).
- Listening to `SceneOpened` alone covers both Open and New (there is no `SceneCreated` event in Maya 2024).
